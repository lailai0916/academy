# Academy 架构说明

## 系统边界

Academy 只服务学生个人用户。账号通过邀请码建立；管理员负责邀请码、AI 接口和教材内容。
平台不包含家长、教师、学校或支付角色。

## 运行结构

| 层   | 技术                                             | 责任                                      |
| ---- | ------------------------------------------------ | ----------------------------------------- |
| Web  | React 19、Vite、React Router、`@lailai/ui`       | 学习、社交、个人与管理界面                |
| API  | Fastify 5、Zod                                   | 认证、权限、计划、练习、AI 与社交业务     |
| 数据 | PostgreSQL、Drizzle ORM                          | 用户、内容、复习事件、FSRS 卡片与社交关系 |
| 调度 | `ts-fsrs`                                        | 根据稳定性、难度和遗忘概率安排下次复习    |
| AI   | OpenAI 兼容 Chat Completions，默认 `gpt-5.6-sol` | 基于已审核内容生成讲解和变式              |
| 边缘 | Caddy                                            | TLS、静态文件、SPA 回退与 `/api` 反向代理 |

## 关键数据流

1. 管理员生成邀请码；数据库只保存 SHA-256 哈希，明文只返回一次。
2. 学生注册后获得随机会话 token；浏览器仅持有 Secure、HttpOnly、SameSite=Strict Cookie，
   数据库只保存 token 哈希。
3. 教材内容按批次预检后导入；数据库记录来源、版次、目标状态与新增、更新、未变数量。草稿
   不进入学生计划，发布前可在内容库中筛选和复核；存在音标、例句、释义或考查要点完整性
   问题的内容不能直接发布。
4. 每日计划先安排当前年级的已发布到期内容，再按每日容量补充新内容；任一学科内容不足时，
   剩余容量自动分配给另一学科。
5. 学生可以按教材单元、到期项目或历史错题建立学习会话；诊断会优先覆盖对应年级已发布
   内容中的不同教材单元。每名学生仅保留一个进行中的学习会话，重复创建请求恢复原会话。
6. 每次回答形成不可变的 `review_events` 记录，并更新对应 `learning_cards` 的 FSRS 状态。
   反应时间评价按选择、拼写、语境填空和默写题型使用不同阈值。
7. 学习会话可暂存或结束；结束后保留已完成记录，未答内容不进入结果。会话结果由事件记录
   生成正确率、反应时间、当前掌握度和本组错题；近 7–90 天记录汇总为学习分析。
8. 至少间隔 24 小时的复习单独进入延迟正确率；稳定期达到 21 天的项目计入长期记忆。
9. 好友申请、接受申请与小组挑战写入站内通知；顶部通知入口不传递敏感学习内容。
10. AI 请求只包含当前教材内容、题目和用户本次回答，不发送用户名或个人档案。

## 安全与隐私

- Argon2id 保存密码；登录和注册有速率限制；写请求校验 Origin；
- 管理权限在 API 强制执行，前端路由隐藏不构成权限边界；
- AI Key 以 AES-256-GCM 加密，密钥只存在生产环境变量；
- API 容器以非 root、只读文件系统和最小 Linux capability 运行；
- PostgreSQL 不暴露公网端口；API 只绑定宿主机 `127.0.0.1:4100`；
- Umami 只加载基础页面统计脚本，不上报答案、用户名或教材内容。

## 当前范围与后续扩展

当前已连通教材单元、分层诊断、错题巩固、会话结果、学习分析、两阶段内容导入、来源追踪与
站内通知。仓库附带的内容量仍仅用于验证产品链路。后续应补充内容审核人、版权记录和批次
回滚，再扩展学科知识图谱与更复杂的知识追踪。社交挑战的实时计分仍需继续完善。
